# FPSO 商机发现系统 — 团队协作规范

> **写给前端同事**：这份文档告诉你怎么和秒搭配合做前端，以及怎么和我（后端负责人）协作。请仔细阅读后再开始。

---

## 1. 分工说明

```
我（后端负责人）负责：
  ✅ Supabase 数据库（表结构、数据）
  ✅ Python 爬虫（自动采集项目信息）
  ✅ 数据维护和更新

你（前端 + 秒搭）负责：
  🎨 所有页面和组件的 UI 设计
  🎨 交互效果、动画、视觉风格
  🎨 数据展示（从接口拿数据显示在页面上）
```

**关键认知**：后端接口已经全部就绪，你不需要管数据从哪来、怎么存的。你只需要调用接口拿 JSON，然后渲染成漂亮的界面。

## 3. 你的自由和不自由

### ✅ 完全自由发挥

- 颜色、字体、圆角、阴影等所有视觉细节
- 页面布局方式（怎么分栏、怎么排列）
- 卡片样式、列表样式、表格样式
- 动画、过渡效果
- 图表类型（饼图、柱状图、雷达图，任选）
- 图标选择
- 暗黑模式（想做就做）
- 任何**纯 UI 层面**的新功能（比如搜索建议下拉、卡片拖拽排序、视图切换等）
- 只要现有接口能查到的数据，怎么展示都行

### ❌ 必须遵守的约束

| 约束 | 原因 |
|------|------|
| **API 返回的字段名不能改** | `name` 就是 `name`，不能写成 `projectName` |
| **API 地址不能改** | 必须用 `https://zbxogsfnhagcavbvhypk.supabase.co/rest/v1` |
| **认证请求头必须带** | apikey + Authorization，每个接口请求都带 |
| **空值字段必须处理** | 15 个字段可能为 null，不处理会白屏 |
| **技术栈必须是 React + TypeScript + Vite** | 别的框架接不上后端 |

## 4. 想加新功能怎么办

如果你在设计界面时想到一个很酷的功能，但不确定现在能不能做，按以下流程：

### 步骤 1：判断

| 情况 | 怎么做 |
|------|--------|
| 功能所需数据**在 mock_data_fpso.json 里能查到** | 直接做 |
| 功能所需数据**不在 mock 里，但你觉得后端应该有** | 问我一嘴 |
| 功能是**纯 UI 交互**（不涉及新数据） | 直接做 |

### 步骤 2：如果数据不在接口里

给我发一条消息，格式如下：

```
新功能：全球项目热力图
需要的额外数据：每个项目的经纬度坐标
现在接口能查到吗：不能
```

我会回复：

| 我的回复 | 你接下来怎么做 |
|----------|--------------|
| "有，我补上" | 我先加数据，你用 mock 占位做 UI |
| "没有但能搞，需要 N 天" | 你先用假数据做 UI 壳子，后续切接口 |
| "数据来源没有，做不了" | 放弃这个功能，别浪费时间 |

## 5. 开发阶段

### 阶段一：纯 UI 开发（你和秒搭独立完成）

1. 秒搭用 `mock_data_fpso.json` 做本地数据源
2. 照着 `FIELD_MAPPING.md` 做页面布局
3. 随便发挥设计创意
4. 我（后端）同时继续完善爬虫和数据库

**这个阶段我们完全互不依赖，各自做各自的。**

### 阶段二：切换到真实接口

1. 把 mock 数据调用替换成真实 API 调用
2. API 代码模板在 `API_DOCUMENTATION.md` 第五节
3. 飞书登录先跳过（anon key 可直接读数据）

### 阶段三：接通后端

把前端项目文件发给我，我帮你：
- 确认接口调用正确
- 接上飞书登录
- 部署上线

## 6. 字段变更同步规则

在我（后端）修改数据库字段时，我会遵循以下规则：

| 我会做 | 我不会做 |
|--------|---------|
| 新增字段 | 删除现有字段 |
| 新增表 | 修改现有字段名 |
| 新增数据 | 修改字段类型 |

**每次加新字段后，我会在群里发一条消息**，格式：

```
[后端更新] projects 表新增字段 `coral_risk_level`，类型 text，含义：珊瑚风险等级。前端可以按需展示。
```

你不用立刻做。想展示的话，下次更新界面时加上就行。
